# AI会話をしない文字起こし

ミニアプリ「文字起こし: ON/OFF」、またはブラウザの「会話」→「文字起こしのみ」から切り替える。専用APIは `/recognition/mode`、入力は `{enabled:true|false}`。PC経由は `/api/recognition/mode`。状態は `/chat/status` の `recognitionMode`。

初期状態はOFF。ONにするとAI会話をOFFにし、XiaoZhiの認識だけを使う。Gemini/Ollamaキーは不要だが、XiaoZhi登録とインターネット接続は必要。音声はXiaoZhi公式クラウドへ送信されるため、ローカルだけの認識ではない。

認識文は本体の吹き出しに15秒表示し、既存のSD会話JSONとDBへユーザー発言として保存する。人物を自動登録しない。AIの推論・返答・読み上げ・MCP操作を本体側で実行しない。発言がタイマーやアラームの指示であっても、このモードでは文章を保存するだけ。

クラウドから届く返答音声・文章・MCPをワーカーで抑止する。公式サービス自体は専用のSTT APIではなく、サーバー内で推論が実行されない保証はない。認識後は接続を閉じ、次の発言に備えて再接続するため、発言間に数秒の待機が入る。

AI会話と文字起こしは排他的。AI会話ONで文字起こし専用モードはOFFとなる。専用モードのON/OFFはSD設定へ保存され、明示的にOFFにした後は起動時にも復帰しない。通常のAI会話OFFは、既に有効な文字起こし専用モードを勝手にON/OFFしない。

テスト: 実際の会話モジュールを実行し、AI OFF・AIキーなしで認識文が1件保存されること、AI応答・音声・道具・プロフィール変更がないこと、停止後の古い認識文を捨てること、モード排他を確認。ブラウザ2種類のJavaScriptと操作ボタンも確認。実音声の聞き取りは別途確認が必要。

実機: 更新 `20261102-000815-47085` の書き込み成功。AI会話OFF・文字起こしOFF・処理停止で起動し、`/recognition/mode` のOFF保存と読み返しを確認。音声は送信していないため、実声の聞き取りは未検証。既存の音量40%、毎朝7:10の予約は維持。アラームの鳴動テストなし。
