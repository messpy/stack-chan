# LANから本体の動作を確認する

本体とスマートフォン・PCを同じWi-Fiへ接続し、本体の「スマホで操作」QRで操作ページを開く。「本体の動作確認」から開始する。PCのUSB中継は不要。本体への直接Wi-Fi接続でも同じページを利用できる。

- カメラを見る: 176×144 JPEGを約1秒ごとに更新。
- 音声を聞く: 本体マイクの16kHz mono PCMをブラウザで連続再生。カメラと併用可能。通信とバッファによる遅延があるため、映像・音声の同期は保証しない。
- 首の向き: 上・下・左・右・正面。左右約17度、上約9度・下約7度の固定位置。
- LED: カラーピッカーで色指定、虹色、消灯。明るさを最大値の約1/4に制限。
- テキスト: 最大200文字を本体内の日本語合成音声で読み上げ、吹き出しにも表示。音量は操作ページの音量欄を使用。

動作確認中はAI会話を一時停止する。読み上げ中は共有I2S機器の競合を避けるためマイクのモニターを一時停止し、読み上げ後に戻す。読み上げた声を本体マイクで同時に中継する機能ではない。

終了ボタン、ページを閉じる／非表示にする、または12秒間リクエストがない場合に終了する。終了時は入力・読み上げ・LED・サーボの保持を停止し、AI会話が有効だった場合は再接続する。タイマー／アラームが鳴る際も動作確認を終了して通知を優先する。

プレビュー画像・モニター音声はSDへ保存せず、クラウドにも送信しない。写真保存・録画・AI認識は動作確認を終了して既存の撮影ボタンから実行する。

## 実装

`archive-lan-monitor.js`がセッション、マイクの上限1秒のキュー、首・LED・読み上げの排他処理を担当する。`lan-archive.js`がドライバーと接続し、`archive-web.js`が既存のQR認証を適用する。

- `/rpc` の `/monitor/start`、`/monitor/status`、`/monitor/stop`、`/monitor/audio`、`/monitor/command`
- GET `/camera/frame?session=...`: JPEG
- GET `/monitor/audio?session=...`: 16-bit little endian PCM、16kHz、mono

ブラウザの音声バッファも上限を設け、遅い通信で音声の遅延が増え続けることを防止する。セッションIDはステータス一覧に公開しない。

## 検証

`firmware`内で `npm run test:lan-monitor`。ドライバーを置き換えたホストテストでセッション排他、PCMの容量と順序、カメラ失敗、マイク開始失敗、読み上げ切り替え、切断、ブラウザ操作を検証する。

実機ビルド・書き込みとスマートフォンでの映像・音声確認は別途必要。通常の`StackChan_update.sh`を使う。

## LIVEと字幕の選択

「カメラ」「音声」のチェックを選び、「LIVEを見る」で開始する。片方だけ、または両方を選べる。開始後にチェックを変えた場合はもう一度「LIVEを見る」で反映する。「LIVEを停止」で映像と音声をまとめて止める。両方を外して開始した場合も停止し、選択を促す。

「字幕を表示（本体・この画面）」は初期状態でオフ。チェックすると、読み上げ中に本体の吹き出しとブラウザの字幕を表示する。ブラウザ字幕は読み上げ完了後も5秒間表示する。オフの場合は字幕を出さない。

音声付きLIVE中の読み上げではマイクを一時的に閉じる。読み上げ中にLIVEを停止した場合は、読み上げ後もマイクを再開しない。


## 方向ボタンの長押し（更新待ち）

カメラ映像の隣に方向パッドを配置。上下左右は押している間だけ移動し、正面は1回押すと中央へ戻る。マウス・タッチ・Space/Enterに対応する。

- 本体の `pose_hold` 操作は50msごとに最大20度/秒で目標角度を更新。1回の更新は100ms分までとし、処理停止後の急な大移動を防ぐ。
- 手動操作範囲は左右±60度、上下5〜60度。ドライバー側の機械的制限も維持する。端では位置コマンドを繰り返さない。
- 操作開始時にサーボの現在位置を読み取り、その位置から動かす。位置を読めない場合は移動を開始せずエラーにする。
- ブラウザは250msごとに長押しを更新。本体は750ms通知がなければ停止。操作ごとのsequenceで、指を離した後に遅れて届いた更新を無視する。
- 指を離す、pointercancel、フォーカス喪失、画面非表示、カテゴリ移動、LIVE停止、動作確認終了で停止。LIVE映像が3秒以上更新されない場合もブラウザから停止する。
- 停止時は最後に送った小さな目標位置で止まり、動作確認終了時にトルクを解除する。サーボ位置フィードバックを連続制御する仕組みではないため、実際の停止はネットワークとサーボの応答時間にも依存する。
- `/monitor/status` で首の準備・移動・上限・目標角度・エラーを取得できる。開始・停止・上限・通信更新切れは内部ログへ記録する。

事前確認：長押し制御テスト、LANモニター8件、ブラウザ操作11件、manifestとdiffチェック通過。ユーザー指定により更新スクリプトは未実行。書き込み後、PCカメラと内部ログで実機確認する。
