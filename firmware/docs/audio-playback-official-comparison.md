# M5Stack公式との音声再生比較と修正

## 比較した実装

- メーカー公式のローカルチェックアウト: `/mnt/data/Development/stackchan/m5stack-official`、remote `m5stack/StackChan`。
- 公式 `firmware/repos.json` は音声基盤として `78/xiaozhi-esp32` **v2.2.4** を指定する。ローカルには依存リポジトリ本体がなかったため、該当タグの公式ソースを参照した。
- https://github.com/78/xiaozhi-esp32/blob/v2.2.4/main/audio/audio_service.cc
- 公式CoreS3: `firmware/main/hal/board/config.h`、`cores3_audio_codec.cc`。

公式は入力・Opus処理・スピーカー出力を別タスクに分け、復号済みPCMをキュー経由で出力する。CoreS3の出力は24kHz。現在の拡張版も24kHzとEspressif Opusデコーダを使っており、デコーダの種類だけが相違点ではない。

拡張版は `embedded:io/audio/out` の同期 `onWritable` から、画面・字幕・SD保存と同じJSマシンでPCMを補充していた。SDKのDMAバッファ約20KBは24kHz mono 16bitで約426ms。JSの画面更新・DB保存等が遅れると、ネットワーク用リングにPCMが残っていてもDMAへ渡せない経路がある。旧ログでは `[playback] rebuffer count=1/2` が確認された。これは原因候補を裏付けるが、実音声を聞かず全原因の特定や聴感の改善を保証するものではない。

## 変更

- 会話音声を `AudioOut.Async` に変更。移動しないSharedArrayBufferにPCMをコピーして渡し、SDKの優先度10の音声タスクでDMA補充する。
- コピー用キューは最大8×8192バイトを1個の大きなSharedArrayBufferで確保し、PSRAMを使用して内部RAMを圧迫しない。ネットワーク用リングはコピー後に解放できるが、コピーはネイティブ出力が使い終わるまで再利用しない。
- 画面側が一時的に止まっても、ネイティブタスクは先渡しされたPCMを再生し続ける。
- 音声データがネットワーク用リングからなくなっただけでは再バッファリングしない。ネイティブキューとDMAに残った音声を考慮し、本当に枯れた場合だけ再バッファリングする。
- XiaoZhiの末尾無音は、DMAの端数ブロックを押し出せる長さを確保し、最後の音節が未送信のまま残ることを防ぐ。
- 最後の音声は、非同期キューの完了後もDMAの保守的な再生待ち時間を確保してからマイクへ戻る。
- 連続会話では前ターンのリング位置を引き継ぎ、以前の音声を再生し直さない。CoreS3ではAsyncが通常のアンプ用ラッパーを通らないため、アンプのサンプルレートも明示設定する。
- 口パクはネイティブの完了コールバック内から直接更新せず、メイン側の定期処理で更新する。旧セッションの完了コールバックは無視する。
- 既存の先読み時間は維持し、単に大きな待ち時間へ変更する方式にはしていない。
- 診断 `playback` に `mode:native-async`、`queuedMs`、`bufferedMs`、`maximumPumpGapMs`、`underruns` を出す。

## 無音検証

`node scripts/lib/archive-playback-buffer.test.mjs`:

- 600ms相当の受信済みPCMからでも、JS停止500ms中にネイティブモデルがPCMを継続消費できる。
- 元リングを即座に上書きしても、先渡ししたPCMコピーの内容は変わらない。
- 12通りのジッタ・折り返し・バックプレッシャーでPCMの順序、欠け、重複を検証。
- キュー上限、出力失敗時に未送信データを消費済みにしないこと、終了後コールバックの無視を検証。

`node --experimental-vm-modules scripts/lib/archive-speaker-selection.test.mjs`:

- 実際のアダプターを実行し、ネイティブ完了とDMA待ちを終えるまで出力を閉じないこと、聞き取りへの復帰が1回だけであることを確認。
- 話者・認識専用モード・会話OFFの既存テストも確認。

ユーザーの夜間無音指定により、音声再生、接続した本体での会話、本体への書き込み・再起動は実施しない。ビルドのみ行う。**本体への反映と、音を出しての最終確認は未実施。** 予約と本体の音量は変更しない。
