## 統合レベルの定義
- **継承済み**: 元PRのHEADをカテゴリブランチの祖先として保持。元PRのコード一式を保持する。
- **追加済み**: 別PRから競合のない新規blob/テスト/設計資料を追加。元PR全体の統合成功を意味しない。
- **競合保留**: 既存ファイルに異なる変更がある。blind overwriteや単純なblob優先選択はしない。
- **受入済み**: 対象環境での統合テスト、CoreS3ビルド、実機の動作とログが揃って初めて判断。

## 音声の共通受入
- マイク取得 → エンコード → WebSocket/API送信 → STT最終確定 → LLM → TTS要求/受信 → PCMデコード → native出力 → DMA排出推定 → マイク再開を、同一 turn/session/request ID で記録する。
- raw USB原本、再構成全文ログ、機密保護済みJSONL、ログ欠落数を分ける。認識本文・音声内容・Authorization・シークレットは共有ログに出さない。
- STT/TTS APIは設定可能なproviderごとにタイムアウト・HTTP status・サイズ・送受信量・キャンセル理由を計測。オフライン時は本体内蔵の限定コマンドとローカル音声をフォールバック候補にする。
- 撮影はTTS途中に強制割込せず、出力解放とカメラresource取得/解放の検証を優先。

## 実機受入・マージ
- まず `bash ~/stackchan.sh --check`。PRは `stackchan-super` に直接マージしない。
- テスト・CoreS3ビルドが成功し、USB同一性、16MiBバックアップとSHA256確認を通った場合のみ書込へ進む。
- 書込成功と起動/Face/会話/写真の成功は別の受入判定。
- 統合元の古い作業ブランチは、内容が保存されていることを再検証した後に削除する。
